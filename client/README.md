# CampusHub Frontend

CampusHub is a React and TypeScript application for browsing campus resources and managing reservations.

## Technology

- React and TypeScript
- Vite
- Native Fetch API
- CSS Modules
- Express and MongoDB backend

## Local Development

Run the following commands from the repository root to install backend dependencies and start the backend:

```powershell
npm.cmd ci
npm.cmd run dev
```

The backend requires a running MongoDB instance and a local `.env` file containing `MONGODB_URI`. See the root `.env-example` for configuration.

If the database has no sample resources, run `npm.cmd run seed` from the repository root.

In a separate terminal, start the frontend:

```powershell
cd client
npm.cmd ci
npm.cmd run dev
```

Open the local URL printed by Vite, normally `http://localhost:5173`.

The Vite development proxy forwards `/api` requests to `http://localhost:3000`. Production hosting requires an equivalent API routing configuration.

## Features

- Browse resources and filter by ROOM, EQUIPMENT, or LAB.
- Select a resource and submit a reservation.
- Validate required times and ensure the end time follows the start time.
- Convert local input times to ISO timestamps for API requests.
- Display an explicit message for HTTP 409 reservation conflicts.
- View active reservations and cancel bookings.
- Reload bookings automatically after successful creation.
- Update and reload bookings after cancellation.
- Display loading, empty, success, and error states.
- Retry resource requests and refresh bookings after service recovery.

## API Contract

The API service is located in `src/api/campushubApi.ts` and follows `../docs/openapi.yaml`.

| Function | Method | Endpoint |
| --- | --- | --- |
| fetchResources | GET | /api/v1/resources |
| createReservation | POST | /api/v1/reservations |
| fetchUserReservations | GET | /api/v1/reservations/user/{userId} |
| cancelReservation | PATCH | /api/v1/reservations/{id}/cancel |

Reservation IDs and statuses are generated by the backend. Requests have a 15-second timeout.

## Validation

Run from `client/`:

```powershell
npm.cmd run build
npm.cmd run lint
```

Both commands passed during Lab 5 development.

Manual checks confirmed invalid time validation, successful booking, duplicate-booking error handling, reservation listing, cancellation, and rebooking the cancelled time slot.

Stopping the backend produced visible HTTP 502 errors in the resource directory and bookings list. Both areas recovered after restarting
